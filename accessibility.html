Digital Inclusion

Inclusion is intentional.

Rest should be available to everyone. This page documents what we've built to lower barriers, what we're working toward, and how to reach us when something isn't working the way it should.

01 · Language Access

The site speaks seven languages.

Translation is built directly into every page — no third-party plugin, no redirect. Select your language below and it applies immediately across the entire site. Your preference is saved for future visits.

Translation is applied site-wide in real time. No page reload required. Your selection is stored locally — it persists across sessions until you change it.

02 · What We've Built

Specific commitments.
Not aspirations.

Each item below is either live in the current build or in active development. We note which is which.

01

Motion Control

The Atmosphere layer — ambient audio, particle effects, and enhanced animations — is off by default. A clearly labelled toggle in the nav gives full control. The site also respects the browser's prefers-reduced-motion setting: animations are suppressed without any user action required.

Live
02

Keyboard Navigation

Every interactive element is reachable and operable with a keyboard alone. Focus indicators are visible and high-contrast. A skip-to-content link appears at the top of every page on first Tab press, allowing keyboard users to bypass repeated navigation.

Live
03

Screen Reader Support

Pages are built with semantic HTML5 — headings, landmarks, lists, and buttons are all structurally correct. Decorative images carry aria-hidden="true". All interactive SVG icons have accessible labels. Navigation regions are labelled with aria-label.

Live
04

No-Script Fallback

All content and navigation are accessible without JavaScript enabled. A <noscript> stylesheet on every page restores scrollability, native cursor, and element visibility — so the site is readable in restricted browser environments.

Live
05

Inclusive Clinical Language

All clinical disclaimers use "provider" rather than "physician." This reflects the full spectrum of licensed care — physicians, nurse practitioners, physician assistants, and other clinicians — without implying a particular type of clinical relationship.

Live
06

Colour & Contrast

Our target is WCAG 2.1 Level AA — a minimum 4.5:1 contrast ratio for body text and 3:1 for large text and UI components. All gold-on-black and cream-on-black pairings have been tested. Interactive elements have visible hover and focus states.

Target: WCAG 2.1 AA
07

Custom Cursor Fallback

The site uses a custom cursor for aesthetic cohesion. If JavaScript is unavailable or disabled, the custom cursor element is hidden and the native browser cursor is restored in full. No user is left without a visible pointer.

Live
08

Touch & Mobile

Interactive elements have a minimum tap target size of 44×44px. Tap highlights are suppressed in favour of visible border and background feedback. The horizontal product gallery responds to both touch swipe and mouse drag. The site is fully tested at 375px viewport width.

Live
03 · Honest Accounting

What we know we haven't
finished yet.

On the Roadmap

  • WCAG 2.2 review — several new criteria added in 2023 are not yet fully audited, including focus appearance and dragging alternatives.
  • Right-to-left language support for Arabic and Hebrew — not available in the current translation system.
  • Protocol Summary PDFs (the one-page provider-ready documents) will be made screen-reader compatible before Forum launch.
  • An independent WCAG audit by a third-party accessibility firm before public launch of Volume 01.
04 · Contact

Feedback is a gift.

If something on this site creates a barrier — a contrast issue, a focus trap, a translation error, anything at all — we want to know immediately. Your report is the fastest path to a fix.
